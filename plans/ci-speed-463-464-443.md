## #464: promtool split over matrix legs

- Every test group in `infrastructure/prometheus-rules-test.yml` gets a
  `name`. Nothing else in the file changes: the diff is the `name:` lines
  and the `interval:` key moving under them.
- `alert-rules` becomes a four-leg matrix. Each leg lists its groups;
  the step builds an anchored `--run='^(a|b|c)$'` from them.
- Packed by measured time (local seconds): leg 1 all fast groups +
  weekday-afternoons + b-suspended (19 s), leg 2 off-at-weekends +
  b-after-activation + late-start (25 s), leg 3 the two (c) groups +
  late-cluster-never-runs (24 s), leg 4 stopped-scheduling + manual-backup +
  suspend-flicker (21 s).
- promtool says SUCCESS and exits 0 when `--run` matches nothing, so each
  leg writes a JUnit report and fails unless it lists as many testcases as
  the leg names groups.
- `check rules` runs in every leg (0.2 s) instead of one leg with a
  step-level `if`, which `TestEveryLintCheckStillGates` forbids for good
  reason.
- Not done: coarsening the backup tests' evaluation or sample resolution.
  `avg_over_time(suspend[98h]) < 0.01` depends on how many samples the
  window holds, and `for: 30m` on the evaluation step, so a coarser test
  would assert something slightly different. The split alone is enough.

Guard: `TestRuleTestGroupsRunOnce` (`ruletestlegs_guard_test.go`).

## #463: a lint-only cache

- `go-lint`: setup-go `cache: false`; an `actions/cache@v4` step holds
  `~/go/pkg/mod`, `~/.cache/go-build` and `~/.cache/golangci-lint`, keyed
  `go-lint-<os>-go<version>-<go.sum hash>-<ISO week>` with restore keys
  that drop the week, then the go.sum hash.
- golangci-lint-action gets `skip-cache: true` so its own entry no longer
  competes for `~/.cache/golangci-lint`.
- Why the week: a per-commit key would save 1.6 GB raw on every run and
  crowd the shared 10 GB cache (5 GB in use today, mostly setup-go entries
  per PR). Per go.sum alone freezes the entry like the action's own did.
  Weekly refresh on main keeps our own packages' build output current; the
  bulk (stdlib and dependencies) only changes with go.sum or Go.
- A PR saves its own entry only when neither it nor main has this week's
  key, the same profile as setup-go's caches today.

Guard: `TestGoLintKeepsItsOwnBuildCache` (`golintcache_guard_test.go`).

## #443: shard script and guards

- `go-test-shards.sh`: every `go list` goes through `list`, a plain
  assignment that dies on a failure or an empty result, so `set -e` is never
  bypassed by a pipe, a process substitution or the old `$(for …)` loop.
  `rest` also fails when it ends up empty.
- The `Go Tests` aggregator checks each result on its own line with
  `|| exit 1`. The old `a && b && c` failed only while it was the last line.
- Guards (written by a separate test author from the acceptance criteria):
  - `TestGoTestShardScriptFailsWhenGoListDoes`: fake `go` on PATH, every
    failure and empty case for `rest` and the named shards.
  - `TestGoTestsAggregatorFailsWhenANeededJobDid`: runs the step script
    with each needed job as failure, cancelled and skipped.
  - `TestGoTestShardsCoverEveryPackage`: `-race` and the other required
    parts are matched in the command with comments stripped.

## Verify

- `go test -count=1 ./pkg/managementapi/...`, golangci-lint, gofmt.
- `bash -n` on the shard script; the shard script under a failing fake
  `go` (old: exits 0 in all three `rest` cases; new: exits 1).
- Every leg's step run locally: 26 groups run, each once.
- CI on the PR: per-leg and lint timings on two consecutive runs.
- Scratch commits that break each new rule (a group left out of the legs,
  the aggregator body, `-race` in a comment, `cache: false` removed),
  pushed, CI red, reverted with a new commit.

## Risks

- Cache size: the lint entry may be 400-600 MB compressed; restoring it
  costs some seconds. Measured on the PR.
- A new rule test group must be added to a leg, or the guard goes red.
  That is the point, and the message says so.
